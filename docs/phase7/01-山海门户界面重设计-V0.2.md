## 0. 一句话结论

在**不新增、不修改任何 API 端点**的前提下，对门户做信息架构与视觉层面的整体重设计：从「单屏调试仪表盘」升级为「**应龙·任务 / 玄武·审批 / 观测（白泽·能力、女娲·演进、夔牛·证据）/ Agent**」三加一导航的工作台，全量保留已冻结的交互契约（V0.2 冻结），解除 D-43 零构建约束引入轻量构建管线（决策官 OQ-2 已预批准方案 A），分四批交付、每批独立可验收。

## 1. 背景与目标

### 1.1 现状与问题（基于 main @ 8d5fe03 实测）

| # | 现状事实 | 问题 |
|---|---|---|
| 1 | `app.js` 542 行单文件、9 个 view 模块合计仅 414 行 | 信息全部挤在一个滚动页，无导航、无路由 |
| 2 | 首页大段区域渲染原始 JSON（`jsonBlock` 直出 evidence/events/insight/report 等） | 非工程人员无法阅读；关键信息埋没 |
| 3 | 任务列表与审批列表平铺，无筛选、无搜索、无分页 | 任务量上来后不可用 |
| 4 | 审批操作只有原始按钮 + 固定文案，无风险分级展示、无影响范围摘要 | 审批决策缺少上下文，误操作风险高 |
| 5 | 取消 / 恢复 / 批准等写操作共用一套简陋确认（`reflectWriteSpec` 镜像注释） | 不同风险等级的操作没有差异化防护 |
| 6 | 无统一视觉规范：颜色、间距、字号散写在 542 行里 | 观感粗糙，"基本不可用"（用户原话） |
| 7 | 状态标签直接显示英文枚举（`queued`/`running`/`paused`…） | 无中文化、无语义分层 |
| 8 | 无空态 / 加载态 / 错误态的统一处理 | 接口慢或失败时界面卡死或无反馈 |

### 1.2 重设计目标

1. **可用**：信息架构清晰——任何功能 ≤2 次点击可达；列表可筛选、可搜索、可分页；审批决策上下文完整。
2. **可信**：状态、错误、空态、危险操作都有明确、一致、中文的语义表达；所有写操作有与风险等级匹配的防护。
3. **可维护**：引入轻量构建（esbuild），前端按页面模块化，设计 Token 统一管理，为后续阶段留扩展位。

### 1.3 硬约束（继承裁决，不可违反）

- **零端点变更**：不新增、不修改、不删除任何 HTTP 端点；不使用任何 websocket / SSE。
- **写契约冻结**：写操作的模态流程、文案、后果描述逐字沿用 `view/write.ts`（该文件已被 12 个文件 98 个断言的契约测试锁定，UI 重写必须逐字复用其文本）。
- **轻量实现优先**：布局与视觉只依赖 CSS/DOM；图表 / diff / 复杂交互让位。
- **既有红线不破**：覆盖率单调门（当前 95.21%，425/425）、宿主绑定安全、错误格式冻结。
- **验收留痕**：每个批次交付物必须含真实浏览器走查截图证据（OQ-1 预裁定：不接受 DOM 断言替代）。

## 5. 页面设计：任务工作台（一级导航「应龙·任务」）

> **数据源声明（本节全部条目共用）**：任务列表唯一数据源为既有端点 `GET /api/tasks`（参数 `limit` / `offset` / `status` / `agentId`；`status` 合法枚举为 `created/queued/running/paused/succeeded/failed/cancelled` 七值，对应 db.ts `task_record.status` CHECK 约束，db.ts:103）。**本系统不存在 `/api/stats` 统计端点**，本节统计卡数据均由前端从列表响应聚合产生。

### FR-T-1 状态统计卡

- **目的**：进入任务页第一眼看到全量任务的状态分布。
- **数据源**：`GET /api/tasks?limit=100`（拉取最近 100 条，前端按 `status` 聚合计数；不新增任何端点）。
- **呈现**：横排六个状态计数卡 + 一个合计卡。六状态使用 STATUS_LABELS 既有中文映射（`queued` 排队中、`running` 运行中、`paused` 已暂停、`succeeded` 已完成、`failed` 失败、`cancelled` 已取消），`created` 显示为「已创建」。
- **交互**：点击某状态卡 = 将列表筛选设为该状态（与 FR-T-2 筛选器联动）；再点一次取消筛选。
- **空态**：某状态计数为 0 时卡片仍显示，数字为 0，样式降低对比度（不隐藏，保持七格布局稳定）。
- **刷新**：随 FR-T-5 轮询周期一起刷新（不单独计时）。

### FR-T-2 列表筛选

- **筛选项**：
  1. 状态下拉：七枚举 + 「全部」（默认全部）。
  2. Agent 下拉：选项从已加载任务的 `agentId` 去重生成 + 「全部」；选中后请求带 `agentId` 参数。
  3. 时间范围：今天 / 近 7 天 / 近 30 天 / 全部（默认近 7 天；前端按 `createdAt` 过滤）。
- **URL 同步**：筛选状态写入地址栏 query（`?status=running&agent=<id>&range=7d`），刷新/分享链接后视图可复现。
- **组合规则**：状态与 Agent 筛选传给服务端（`GET /api/tasks?status=…&agentId=…`）；时间范围为前端过滤（服务端无时间参数，如实说明，不虚构）。

### FR-T-3 任务列表

- **列定义**（逐列给出字段出处，全部为 `task_record` 既有列或其派生）：

| 列 | 字段 | 呈现规则 |
|---|---|---|
| 任务 | `taskId` | 显示前 8 位短码，悬停 tooltip 显示完整 taskId；点击进详情 |

### FR-T-4 状态徽章与滞留警告

- **徽章颜色映射**（沿用 §10 语义色）：

| status | 文案 | 颜色 |
|---|---|---|
| `created` | 已创建 | 中性灰 |
| `queued` | 排队中 | 中性蓝 |
| `running` | 运行中 | 主色蓝 |
| `paused` | 已暂停 | 警示橙 |
| `succeeded` | 已完成 | 成功绿 |
| `failed` | 失败 | 危险红 |
| `cancelled` | 已取消 | 中性灰 |

- **running 滞留判定**（与 view/tasks.ts 既有 `runningWarning` 同一口径）：`status === 'running'` 且 `endedAt` 为空且运行时长超过阈值时，该行状态徽章旁追加 ⚠ 警告标记，tooltip 提示「该任务运行时间异常，可能是孤儿运行」。
- **警告出口动作**：点击警告行的操作项为**「显式崩溃恢复」（crash-recovery）**——出口是崩溃恢复，**不是取消**（取消按钮在该行不出现，防止误杀仍在正常执行的独立进程任务）。取消仅在未命中 runningWarning 的 `running` 行可见。

### FR-TD 任务详情页（`/tasks/:id`）

- **FR-TD-4 事件流区**：`GET /api/tasks/:id/events` 返回数组按时间正序展示，每行=序号、`type`、`time`、`payload`（payload 默认折叠，点击展开）。过滤器：事件 type 多选 + 时间范围（`task_event` 无 stepIndex 列，不提供 step 维度过滤）。

- **FR-TD-7 操作区**：`取消`（非终态）、`续跑`（paused）、`显式崩溃恢复`（runningWarning 命中时），行为全部见 §8。

## 8. 写操作通用规范（FR-WR）

适用于全部 5 个写端点（approve / deny / cancel / resume / crash-recovery）。

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-WR-1 | **确认分级**（全部沿用已测契约文案，逐字复用，禁止改写）：① 常规确认（cancel queued/paused 等）：浏览器 confirm，文案=view/write.ts cancelModeFor 非 running 分支 hint：「queued/paused 立即取消（既有 CAS 语义）；paused 取消将连带 pending 审批作废」；② 高危确认（cancel running）：confirm，文案=cancelModeFor running 分支 hint：「该任务运行于独立进程，仅支持强制中止（下一个原子调用边界生效，模型调用不打断；graceful 仅执行进程内可见）」；③ 超危确认（crash-recovery）：confirm，文案=confirmCrashRecoveryText：「将把所有 Running 任务（当前 ${runningCount} 个）标记为 Failed(CrashRecovery)，并执行孤儿快照清理、pending 审批作废与 trace 索引对账。请先确认这些任务的执行进程确实已不存在——正在执行的任务会被误杀且不可恢复。确认继续？」；④ approve/deny：不弹确认，approveActionHint 常驻说明四态文案逐字=「approve 只写决议（任务保持挂起）；deny 为任务级终局（cancelled/approval_denied）」「已批准，待续跑——点击「续跑」以独立进程执行（resumedBy=manual-resume）」「任务状态 ${taskStatus} 非挂起——审批不可决议（可能已被惰性超时终局，刷新查看）」「该请求已终局（只读）」，点击即提交。 | 各级文案与 view/write.ts 逐字符一致 |

## 9. 工程化方案（OQ-2 已裁定：方案 A）

### 9.1 背景

D-43 冻结了「单文件 app.js、零构建步骤」形态，实践中异化为 src/portal/public/app.js（542 行）手工镜像 src/portal/view/ 9 个 TS 模块（414 行）的重复维护。本次重设计将前端推向约 3000 行体量，双份手工维护不可持续，必须有构建纪律。

### 9.2 关键事实

server.ts 运行期从 repoRoot 定位 public/ 静态目录并直读该目录文件（不存在「构建产物复制进包」的步骤）——构建产物直写 src/portal/public/ 即可被 serve，运行期零依赖成立。

### 9.3 方案 A（批准三条件为硬约束）

- 条件① 构建产物（单文件 JS+CSS）直接输出到 `src/portal/public/` 并**提交入库**；源码迁入 `src/portal/ui/`，由 esbuild（单一 devDependency）打为单文件 IIFE 产物。
- 条件② `package.json` 只允许 devDependencies 新增 esbuild、scripts 新增 `build:portal`；dependencies 零新增，运行期零新依赖。
- 条件③ 提供「产物新鲜度」测试：进程内运行构建并与入库产物逐字节比对——作为 7-1 批硬 DoD，防源码与产物漂移。
- D-43 口径修订：守护的是「运行期零依赖」而非「禁止构建」；D-43 约束从「禁止构建」收窄为「禁止运行期依赖」，门禁形态（单文件、零 CDN、无框架运行时）不变。
- 覆盖率基线：main @ 8d5fe03 为 425/425 通过、行覆盖 95.21%，全批次单调不降。

### 9.4 方案 B（备选，已被裁定否决）

运行时加载 view 模块、废除 public/app.js。否决原因：需改 server.ts 路由与 dist 构建方式，违反 API 契约零改动约束，安全风险上升。仅记录，不展开。

### 10.4 组件规范

- **按钮**（4 态齐全：默认/悬停/聚焦/禁用）：primary=实底主色白字；secondary=白底灰边；danger=实底 danger 白字（仅不可撤销/高危动作）；ghost=无边框（次级操作）。高危按钮悬停加深一档。
- **输入**：文本输入、下拉、搜索框统一高度 32px、sm 圆角、聚焦显示主色 outline（2px）；校验失败红边+错误文案紧贴输入框下方。
- **表格**：行高 40px、斑马纹（`--bg-primary`/`--bg-secondary` 交替）、表头粘性、无数据时显示空状态组件。
- **卡片**：白底、md 圆角、sm 阴影、16px 内边距、标题行与内容区间 8px。
- **弹层**：确认对话框居中模态（遮罩 `rgba(15,23,42,.4)`，Esc 与点击遮罩均不关闭，必须显式选择）；Toast 右上角滑入，info/success 3 秒自动消失，error 常驻至手动关闭。
- **状态徽章**：圆点+文字组合（不单独依赖颜色，色盲可辨）；七任务状态/四风险档颜色见 §10.2。
- **空状态**：居中图标区（40px 灰阶图形）+一句话说明+主操作按钮（若有），文案按各 FR 空态口径。
- **连接状态区**：绿点「已连接」/灰点+重连按钮「已断开」/琥珀点「连接中」；断连时全局内容区降透明度至 0.6 并禁止写操作按钮点击。

### 10.5 响应式与可访问性

- 栅格：12 列，间距 16px；任务/审批/Agent 列表的最小支持宽度 1280px，观测页 1024px；低于最小宽度时主区横向滚动、导航保持可见。
- 缩放：100%/125%/150% 下布局不破；文本随系统缩放，等宽 id 区允许截断+悬停全文。
- 对比度：正文/操作文本 ≥4.5:1（AA）；图标按钮须备文本标签或 aria-label。
- 键盘：所有交互元素可 Tab 到达；Enter 触发主操作、Esc 关闭非模态浮层；确认对话框内 Tab 循环。
- 动效：仅过渡态（150ms ease），不做装饰动画；`prefers-reduced-motion` 时全部禁用。

## 11. 异常与边界场景

1. **空数据**：各列表空态按 FR 口径；筛选无结果显示「当前筛选无匹配」，不显示「无数据」。
2. **Token 失效**：写操作返回 401 → 顶部 Token 区展开并定位错误文案「Token 无效或已过期」，不自动跳转；读操作 401 → 内容区显示「认证失效，请更新 Token 后重试」，停止轮询。
3. **服务断开**：任一读请求连续失败 2 次 → 判定断连（网络错误/5xx 计入；401/403 不计入），显示连接状态区「已断开」；恢复后自动重新拉取当前页数据并恢复轮询。断连期间写按钮禁用。
4. **并发冲突**：写操作 409（含 `invalid_transition` 等稳态冲突）→ Toast 显示真实 conflictCode 语义 +「已刷新」，自动重新拉取该实体最新状态，不保留本地旧表单态。
5. **审批决议竞态**：用户打开详情时审批已被其他操作者决议 → 详情区显示最终决议与 decidedAt，操作按钮隐藏，提示「该审批已由其他操作处理」。
6. **长时间运行任务**：duration 列实时刷新；超过 runningWarning 阈值的任务在列表/详情显示运行过久提醒（沿用现有判定与文案）。
7. **跨进程任务取消**：`cross_process` 模式确认对话框明确「仅支持强制中止（下一个原子调用边界生效）」语义，不承诺立即终止（见 FR-WR-1）。
8. **恢复包过期/缺失**：crash-recovery 返回错误 → Toast 显示真实错误文案，并给出 CLI 兜底 `shanhai task run <taskId> --resume --resumed-by manual-resume`。
9. **多标签页同时操作**：不做跨标签协同；以服务端状态为准，冲突按第 4 条处理。
10. **轮询性能**：观测页三段轮询互相独立；某一段失败不影响其他段；页面隐藏（`visibilitychange`）时暂停全部轮询。
11. **超长文本**：长文本超过 60 字符截断+省略号+title 悬停全文；id 一律等宽显示前 8 位+悬停复制全文（任务无标题字段，V0.1「标题」表述更正）。
12. **浏览历史**：路由变更写入 history；直接访问详情页 URL 可独立打开（深链接），实体不存在时显示「记录不存在或已被清理」+ 返回列表按钮。
