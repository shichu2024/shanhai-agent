## 0. 一句话结论

在**不新增、不修改任何 API 端点**的前提下，对门户做信息架构与视觉层面的整体重设计：从「单屏调试仪表盘」升级为「**应龙·任务 / 玄武·审批 / 观测（白泽·能力、女娲·演进、夔牛·证据）/ Agent**」三加一导航的工作台，全量保留已冻结的交互契约（V0.2 冻结），解除 D-43 零构建约束引入轻量构建管线（决策官 OQ-2 已预批准方案 A），分四批交付、每批独立可验收。

## 1. 背景与目标

### 1.1 现状与问题（基于 main @ 8d5fe03 实测）

| # | 现状事实 | 问题 |
|---|---|---|
| 1 | `app.js` 542 行单文件、9 个 view 模块合计仅 414 行 | 信息全部挤在一个滚动页，无导航、无路由 |
| 2 | 首页大段区域渲染原始 JSON（`jsonBlock` 直出 evidence/events/insight/report 等） | 非工程人员无法阅读；关键信息埋没 |
| 3 | 任务列表与审批列表平铺，无筛选、无搜索、无分页 | 任务量上来后不可用 |
| 4 | 审批操作只有原始按钮 + 固定文案，无风险分级展示、无影响范围摘要 | 审批决策缺少上下文，误操作风险高 |
| 5 | 取消 / 恢复 / 批准等写操作共用一套简陋确认（`reflectWriteSpec` 镜像注释） | 不同风险等级的操作没有差异化防护 |
| 6 | 无统一视觉规范：颜色、间距、字号散写在 542 行里 | 观感粗糙，"基本不可用"（用户原话） |
| 7 | 状态标签直接显示英文枚举（`queued`/`running`/`paused`…） | 无中文化、无语义分层 |
| 8 | 无空态 / 加载态 / 错误态的统一处理 | 接口慢或失败时界面卡死或无反馈 |

### 1.2 重设计目标

1. **可用**：信息架构清晰——任何功能 ≤2 次点击可达；列表可筛选、可搜索、可分页；审批决策上下文完整。
2. **可信**：状态、错误、空态、危险操作都有明确、一致、中文的语义表达；所有写操作有与风险等级匹配的防护。
3. **可维护**：引入轻量构建（esbuild），前端按页面模块化，设计 Token 统一管理，为后续阶段留扩展位。

### 1.3 硬约束（继承裁决，不可违反）

- **零端点变更**：不新增、不修改、不删除任何 HTTP 端点；不使用任何 websocket / SSE。
- **写契约冻结**：写操作的确认文案、状态提示、模式选择逐字沿用 `src/portal/view/write.ts`（该模块已被 **1 个测试文件 16 处断言**锁定——tests/wp6b-batch3-portal-write.test.ts；UI 重写必须逐字复用其文本，不得改写）。
- **轻量实现优先**：布局与视觉只依赖 CSS/DOM；图表 / diff / 复杂交互让位。
- **既有红线不破**：覆盖率单调门（当前 95.21%，425/425）、宿主绑定安全、错误格式冻结。
- **验收留痕**：每个批次交付物必须含真实浏览器走查截图证据（OQ-1 预裁定：不接受 DOM 断言替代）。

## 2. 需求范围

### 2.1 In Scope（做什么）

- 门户整体信息架构重设计：导航、路由、页面布局、视觉规范。
- 任务工作台：列表（筛选/搜索/分页/统计）、详情（状态时间线/输入/事件流/证据区/关联区/操作区）。
- 审批中心：待办列表（筛选/排序）、审批详情（影响范围/决议操作/参数摘要/已决议区）。
- 观测面板：运行总控、能力视图、演进视图、证据查询。
- Agent 目录与详情：能力卡、洞察、趋势、报告、能力下钻。
- 前端工程化：esbuild 构建管线 + 产物新鲜度契约测试（方案 A，OQ-2 已预批准）。
- 神兽体系在命名与信息架构层面的落地（§15）。

### 2.2 Out of Scope（明确不做什么）

- 任何 API 端点的新增、修改、删除（含参数语义变更）。
- 任务创建 / 编辑界面（门户只做消费与操作，不做生产）。
- 登录 / 多用户 / 权限体系（Token 输入沿用现状）。
- 移动端适配（桌面优先，窄屏仅保证不横向滚动）。

- 后端渲染（SSR）或服务端模板改造。
- 「触发反思」「演进决策（confirm/dismiss）」等不存在于当前写面的操作。

## 5. 页面设计：任务工作台（一级导航「应龙·任务」）

> **数据源声明（本节全部条目共用）**：任务列表唯一数据源为既有端点 `GET /api/tasks`，参数面 = `limit` / `offset` / `status` / `agentId`（api.ts:72-90 实测）。`status` 合法枚举为**六值** `queued/running/paused/succeeded/failed/cancelled`（api.ts:33 参数白名单）；库内 `task_record.status` 为七值 CHECK（含 `created`，db.ts:103）——created 行可在列表出现与统计，但**不可作为服务端筛选条件**（传即 400，如实标注）。**本系统不存在 `/api/stats` 统计端点**，本节统计卡数据均由前端从列表响应聚合产生。

### FR-T-1 状态统计卡

- **目的**：进入任务页第一眼看到全量任务的状态分布。
- **数据源**：`GET /api/tasks?limit=100`（拉取最近 100 条，前端按 `status` 聚合计数；不新增任何端点）。
- **呈现**：横排**七个状态计数卡 + 一个合计卡**（七状态 = 库内七值：created 已创建 / queued 排队中 / running 运行中 / paused 已暂停 / succeeded 已完成 / failed 失败 / cancelled 已取消，中文映射沿用 view/tasks.ts STATUS_LABELS 同款词表）。
- **交互**：点击状态卡 = 将列表筛选设为该状态（与 FR-T-2 联动）；再点一次取消筛选。**例外如实标注**：created 卡点击为**前端本地过滤**（服务端参数白名单无 created，api.ts:33），卡片 tooltip 明示。
- **空态**：某状态计数为 0 时卡片仍显示，数字为 0，样式降低对比度（不隐藏，保持八格布局稳定）。
- **刷新**：随 FR-T-5 轮询周期一起刷新（不单独计时）。

### FR-T-2 列表筛选

- **筛选项**：
  1. 状态下拉：**六枚举**（api.ts:33 白名单）+ 「全部」（默认全部）。
  2. Agent 下拉：选项从已加载任务的 `agentId` 去重生成 + 「全部」；选中后请求带 `agentId` 参数。
  3. 时间范围：今天 / 近 7 天 / 近 30 天 / 全部（默认近 7 天；前端按 `createdAt` 过滤）。
- **URL 同步**：筛选状态写入 hash 内查询串（`#/tasks?status=running&agent=<id>&range=7d` 形态，前端路由自有状态），刷新/分享链接后视图可复现。
- **组合规则**：状态与 Agent 筛选传给服务端（`GET /api/tasks?status=…&agentId=…`）；时间范围为前端过滤（服务端无时间参数，如实说明，不虚构）。

### FR-T-3 任务列表

- **列定义**（逐列给出字段出处，全部为 `task_record` 既有列或其派生）：

| 列 | 字段 | 呈现规则 |
|---|---|---|
| 任务 | `taskId` | 显示前 8 位短码，悬停 tooltip 显示完整 taskId；点击进详情 |
| Agent | `agentId` | 纯文本 |
| 状态 | `status` | 徽章着色（映射见 FR-T-4） |
| 尝试 | `attemptCount` | 数字；0 显示 `0` |
| 模型调用 | `modelCallCount` | 数字 |
| Token | `tokensUsed` | 千分位格式化 |
| 创建时间 | `createdAt` | `YYYY-MM-DD HH:mm:ss`（本地时区） |

- **排序**：`createdAt` 倒序（服务端默认序 taskManager.listTasks：`ORDER BY createdAt DESC, rowid DESC`，不新增排序参数）。
- **分页**：page size 20（`limit=20&offset=` 翻页，total 为过滤后全量计数不随分页缩放），页脚显示「第 N 页 / 共 M 条」。
- **行内操作**（按状态出现）：
  - `详情`：所有状态可见。
  - `取消`：**仅 `queued/running/paused` 可见**（taskManager.cancel 三分支实测，taskManager.ts:676 起；created 与终态不出取消按钮——created 强行取消只会得到「状态为 created，不可取消」普通错误，UI 不提供该路径）。行为见 §8 FR-WR-1/2。
  - `续跑`：仅 `paused` 可见；行为见 §8 FR-WR-4。
  - `显式崩溃恢复`：仅当 runningWarning 命中（见 FR-T-4）时在行内出现；该操作为**全局端点** `POST /api/portal/crash-recovery`（无 :id，api.ts:301），确认文案已明示全局性；行为见 §8。
- **搜索**：输入框按 **taskId 前缀匹配**过滤当前已加载页（`task_record` 无 title/名称列，本期不提供标题搜索；占位符明示「按任务 ID 前缀搜索」）。
- **空态**：无结果时显示「当前筛选无任务」+ 清除筛选按钮。

### FR-T-4 状态徽章与滞留警告

- **徽章颜色映射**（沿用 §10 语义色）：

| status | 文案 | 颜色 |
|---|---|---|
| `created` | 已创建 | 中性灰 |
| `queued` | 排队中 | 中性蓝 |
| `running` | 运行中 | 主色蓝 |
| `paused` | 已暂停 | 警示橙 |
| `succeeded` | 已完成 | 成功绿 |
| `failed` | 失败 | 危险红 |
| `cancelled` | 已取消 | 中性灰 |

- **running 滞留判定**（与 view/tasks.ts 既有 `runningWarning` 同一口径）：`status === 'running'` 且 `endedAt` 为空且运行时长超过阈值时，该行状态徽章旁追加 ⚠ 警告标记，tooltip 提示「该任务运行时间异常，可能是孤儿运行」。
- **警告出口动作**：点击警告行的操作项为**「显式崩溃恢复」**（全局 crash-recovery）——出口是崩溃恢复，**不是取消**（取消按钮在该行不出现，防止误杀仍在正常执行的独立进程任务）。取消仅在未命中 runningWarning 的 `running` 行可见。

### FR-T-5 轮询

- 列表页打开期间每 5 秒重新拉取当前筛选下的第一页；`document.visibilitychange` 进入不可见时暂停轮询，恢复可见时立即拉一次并重启计时器（沿用 FR-G-4 全局规则）。
- 轮询不重置用户已展开的筛选与页码。

### FR-TD 任务详情页（`#/tasks/:id`）

**数据源**：`GET /api/tasks/:id`（头部与本页主体）、`GET /api/tasks/:id/events`（事件流）、`GET /api/tasks/:id/evidence`（证据区）。轮询 3 秒（任务处于非终态时），终态后停止。

- **FR-TD-1 头部信息区**：完整 `taskId`（等宽字体）+「复制」按钮；状态徽章；`agentId`；`agentVersionId`；`createdAt`；`endedAt`（进行中显示「—」）；`attemptCount`；`modelCallCount`；`tokensUsed`；`cancelReason`（仅取消任务显示）。
  - **明确删除 V0.1 的虚构字段**：`current_step/total_steps` 步进进度、`approval_mode`、来源 issue（`#number title`）、所属项目、恢复点摘要、`is_zombie_running` 标记——`task_record` 无这些列，详情页一律不出现。
- **FR-TD-2 时间线区**：如实呈现两个时间点——`createdAt`（创建）→ `endedAt`（结束，进行中显示「进行中」）。中间无阶段节点（系统无 step 概念，不虚构进度条）。
- **FR-TD-3 输入区**：`input` 字段原文展示（jsonBlock 美化、超长折叠为前 50 行 + 「展开全部」）。
- **FR-TD-4 事件流区**：`GET /api/tasks/:id/events` 返回数组按时间正序展示。事件行字段以 **TraceEnvelope 实测键**为准（traceRecorder.ts:13-26）：每行 = `eventId`（短码）、`eventType`、`timestamp`（本地化）、`callNo` / `callKind` / `attemptNo`、事件差异载荷字段（默认折叠，点击展开）。过滤器：`eventType` 多选 + 时间范围（事件无 stepIndex 维度，不提供 step 过滤）。
- **FR-TD-5 证据区**：`GET /api/tasks/:id/evidence` 返回数组，每行=证据 `ref`（等宽，可点击跳「观测·夔牛·证据」页查看）+ `kind`。无证据时显示「本任务未登记证据引用」。
- **FR-TD-6 关联区**：`parentTaskId` 存在时显示「父任务」链接（点击跳对应详情）；`children` 显示子任务计数 + 子任务列表（每行=taskId 短码 + status 徽章，可点击）。均无则整区显示「无关联任务」。
- **FR-TD-7 操作区**：`取消`（仅 queued/running/paused）、`续跑`（paused）、`显式崩溃恢复`（runningWarning 命中时，全局端点），行为全部见 §8。

## 6. 玄武·审批中心设计

> **数据源声明（实测口径）**：
> - 列表 `GET /api/approvals`，**唯一查询参数 `pending=true`**（api.ts:97-100；approval.ts list 仅支持 pendingOnly）。列表投影列（approval.ts:95-107 SELECT 实测）：`requestId / taskId / toolId / decision / requestedAt / timeoutAt / callRef / agentVersionId / contentHash / taskStatus / timeoutRemainingMs`，服务端固定 `ORDER BY requestedAt DESC`（approval.ts:103）。**列表投影不含 `riskLevel` 与 `decidedAt`**——风险档与决议时间仅在详情页可见；列表也不提供 riskLevel 筛选（无该字段，如实标注）。
> - 详情 `GET /api/approvals/:id`（show 返回 `request`（全行，含 riskLevel/decidedAt/timeoutAt）+ `binding`（agentVersionId/contentHash/snapshotBytes）+ `snapshot`（savedAt/contextBytes 元信息）+ `argsDigest`（挂起调用参数摘要），approval.ts:109-134）。
> - 行模型 `approval_request`（db.ts:137 附近，`decision` CHECK 四枚举 `pending/approved/denied/superseded`；列为 `requestId/taskId/agentVersionId/toolId/riskLevel/requestedAt/decision/decidedAt/timeoutAt/callRef`），全部字段 camelCase。

### 6.1 审批列表（FR-A-1..4）

- **FR-A-1 列表**：服务端返回 `requestedAt` DESC（最新在前，approval.ts:103 实测）；**待办视图前端重排为 `requestedAt` 正序**（等待最久置顶——超时风险优先，前端排序，服务端无排序参数）。分页 20/页（前端分页）。列定义：

  | 列 | 来源 | 说明 |
  |---|---|---|
  | 审批 ID | requestId | **前 8 位短码**（无 `#` 前缀——requestId 为 UUID 非编号），等宽字体，悬停显全 |
  | 任务 | taskId 短码（+ taskStatus 徽章，列表内联 approval.ts:99） | 点击跳任务详情 |
  | 工具 | toolId | 原值 |
  | 决议 | decision | 四枚举徽章（pending 待决议橙 / approved 已批准绿 / denied 已否决红 / superseded 已作废灰） |
  | 请求时间 | requestedAt | 本地化 |
  | 超时倒计时 | timeoutRemainingMs（列表内联，approval.ts:107） | FR-A-3 |

- **FR-A-2 待办视图**：`GET /api/approvals?pending=true`，为审批页默认视图；列同上。
- **FR-A-3 超时倒计时**：`timeoutRemainingMs` 随轮询刷新（秒级本地递减为可选增强项）；<5min 红色闪烁。超时后：**下次任一读请求触发惰性超时判定**，该请求 `decision='denied'` + 任务终局（onTimeout=deny→`cancelled(approval_timeout)` / fail→`failed Policy(ApprovalTimeout)`，approval.ts applyLazyTimeouts 段实测）→ 该行自动移出待办视图。
- **FR-A-4 筛选**：`decision` 四枚举（pending/approved/denied/superseded）**前端本地过滤**（服务端参数面仅 `pending=true`，api.ts:97-100——不虚构端点参数）。riskLevel 不提供列表筛选（列表投影无该字段）。

### 6.2 审批详情（FR-AD-1..6）

- **FR-AD-1 详情头部**：requestId / taskId / **toolId** / **riskLevel（L0..L4 徽章，show() `request` 全行；L3/L4 红色加粗）** / requestedAt / decidedAt（已决议时）/ 任务状态徽章（数据源：从列表进入时携带列表内联 `taskStatus`（approval.ts:99 联查）；深链接直入时补一次既有 `GET /api/tasks/:id`——非新增端点）。**删除 V0.1 的 `action` 字段与 `confirmation_token` 概念**（approval_request 无 action 列；confirmation_token 全库零命中）。
  固定提示条**逐字**引 `view/write.ts` `approveActionHint`（已测契约，禁止改写）：
  - pending + 任务 paused：**「approve 只写决议（任务保持挂起）；deny 为任务级终局（cancelled/approval_denied）」**；
  - approved + 任务 paused：**「已批准，待续跑——点击「续跑」以独立进程执行（resumedBy=manual-resume）」**；
  - pending + 任务非 paused：**「任务状态 ${taskStatus} 非挂起——审批不可决议（可能已被惰性超时终局，刷新查看）」**；
  - 已终局：**「该请求已终局（只读）」**。
- **FR-AD-2 批准/拒绝**：`POST /api/approvals/:id/approve`、`POST /api/approvals/:id/deny`。二次确认 = **前端本地确认弹窗**（明示：纯前端交互态，系统无服务端签发确认令牌的概念）。拒绝后果按上引提示条如实告知为任务级终局。
- **FR-AD-3 参数摘要区**：展示 show() 返回的 `argsDigest`（挂起工具调用参数的 sha256 摘要前 16 位，等宽字体）+ `snapshot.savedAt` / `snapshot.contextBytes`（快照保存时间与字节量）+ `binding.contentHash`（版本内容哈希）。**服务端不返回明文入参快照**（PauseContext 不离开服务端，approval.ts:109-134 实测投影）——前端不展示、不缓存明文参数。redaction 已在服务端完成（玄武），前端原样渲染摘要不重加工。
- **FR-AD-4 已决议区**：`decision` / `decidedAt`（camelCase）/ 决策来源；批准后的推进指引给出 CLI 兜底命令 **`shanhai task run <taskId> --resume --resumed-by manual-resume`**（cli.ts:271-275 实测形态；`shanhai resume` 与 `--from-package` 不存在）。
- **FR-AD-5 并发冲突**：提交前重查详情，`decision≠pending` 时提示「该审批已被处理」并刷新（乐观读，服务端 CAS 为最终裁决——后到方得 409 already_decided）。
- **FR-AD-6 超时倒计时**：同 FR-A-3 口径（详情页可按 `request.timeoutAt` 本地计算）。

## 9. 工程化方案（OQ-2 已裁定：方案 A）

### 9.1 背景

D-43 冻结了「单文件 app.js、零构建步骤」形态，实践中异化为 src/portal/public/app.js（542 行）手工镜像 src/portal/view/ 9 个 TS 模块（414 行）的重复维护。本次重设计将前端推向约 3000 行体量，双份手工维护不可持续，必须有构建纪律。

### 9.2 关键事实

server.ts 运行期从 repoRoot 定位 public/ 静态目录并直读该目录文件（不存在「构建产物复制进包」的步骤）——构建产物直写 src/portal/public/ 即可被 serve，运行期零依赖成立。

### 9.3 方案 A（批准三条件为硬约束）

- 条件① 构建产物（单文件 JS+CSS）直接输出到 `src/portal/public/` 并**提交入库**；源码迁入 `src/portal/ui/`，由 esbuild（单一 devDependency）打为单文件 IIFE 产物。
- 条件② `package.json` 只允许 devDependencies 新增 esbuild、scripts 新增 `build:portal`；dependencies 零新增，运行期零新依赖。
- 条件③ 提供「产物新鲜度」测试：进程内运行构建并与入库产物逐字节比对——作为 7-1 批硬 DoD，防源码与产物漂移。
- D-43 口径修订：守护的是「运行期零依赖」而非「禁止构建」；D-43 约束从「禁止构建」收窄为「禁止运行期依赖」，门禁形态（单文件、零 CDN、无框架运行时）不变。
- 覆盖率基线：main @ 8d5fe03 为 425/425 通过、行覆盖 95.21%，全批次单调不降。

### 9.4 方案 B（备选，已被裁定否决）

运行时加载 view 模块、废除 public/app.js。否决原因：需改 server.ts 路由与 dist 构建方式，违反 API 契约零改动约束，安全风险上升。仅记录，不展开。

### 10.4 组件规范

- **按钮**（4 态齐全：默认/悬停/聚焦/禁用）：primary=实底主色白字；secondary=白底灰边；danger=实底 danger 白字（仅不可撤销/高危动作）；ghost=无边框（次级操作）。高危按钮悬停加深一档。
- **输入**：文本输入、下拉、搜索框统一高度 32px、sm 圆角、聚焦显示主色 outline（2px）；校验失败红边+错误文案紧贴输入框下方。
- **表格**：行高 40px、斑马纹（`--bg-primary`/`--bg-secondary` 交替）、表头粘性、无数据时显示空状态组件。
- **卡片**：白底、md 圆角、sm 阴影、16px 内边距、标题行与内容区间 8px。
- **弹层**：确认对话框居中模态（遮罩 `rgba(15,23,42,.4)`，Esc 与点击遮罩均不关闭，必须显式选择）；Toast 右上角滑入，info/success 3 秒自动消失，error 常驻至手动关闭。
- **状态徽章**：圆点+文字组合（不单独依赖颜色，色盲可辨）；七任务状态 / 五风险档（L0..L4）颜色见 §10.2。
- **空状态**：居中图标区（40px 灰阶图形）+一句话说明+主操作按钮（若有），文案按各 FR 空态口径。
- **连接状态区**：绿点「已连接」/琥珀点「重连中」/灰点+重连按钮「已断开」（三态判定见 FR-G-3 / §11-3）；断连时全局内容区降透明度至 0.6 并禁止写操作按钮点击。

### 10.5 响应式与可访问性

- 栅格：12 列，间距 16px；任务/审批/Agent 列表的最小支持宽度 1280px，观测页 1024px；低于最小宽度时主区横向滚动、导航保持可见。

- 对比度：正文/操作文本 ≥4.5:1（AA）；图标按钮须备文本标签或 aria-label。

## 11. 异常与边界场景

1. **空数据**：各列表空态按 FR 口径；筛选无结果显示「当前筛选无匹配」，不显示「无数据」。
2. **Token 失效**（TASK-128 修订：文案去技术化，用户不应需要理解 Token）：写操作返回 401 → 定位错误文案「登录状态已失效——请从启动门户的终端重新打开（启动时会自动完成登录，无需手动操作）」，不自动跳转；读操作 401 → 内容区显示同口径登录状态失效提示，停止轮询。会话由 CLI 每次启动自动拉起浏览器经 `#token=` fragment 送达（见 FR-G-1 TASK-128 修订），常规本地使用不出现口令操作。
3. **服务断开**：任一读请求连续失败 2 次 → 判定断连（网络错误/5xx 计入；**401/403 不计入**——分别走第 2 条与 Host 拒绝专属处理），连接状态区显示「重连中」（黄）；持续 30s 未恢复 → 「已断开」（红）；恢复后自动重新拉取当前页数据并恢复轮询。断连期间写按钮禁用。
4. **并发冲突**：写操作 409（实码 `already_decided` / `task_not_paused` / `timeout_applied` / `version_mismatch` / `cross_process_graceful_unsupported`，errormap.ts:7-10）→ Toast 显示真实 code 语义 +「已刷新」，自动重新拉取该实体最新状态，不保留本地旧表单态。
5. **审批决议竞态**：用户打开详情时审批已被其他操作者决议 → 详情区显示最终决议与 decidedAt，操作按钮隐藏，提示「该审批已由其他操作处理」。
6. **长时间运行任务**：duration 列实时刷新；超过 runningWarning 阈值的任务在列表/详情显示运行过久提醒（沿用现有判定与文案）。
7. **跨进程任务取消**：running 任务 graceful 请求被服务端前置拦截（409 `cross_process_graceful_unsupported`，api.ts:277-285），确认对话框明确「仅支持强制中止（下一个原子调用边界生效）」语义，不承诺立即终止（见 FR-WR-1）。
8. **崩溃恢复失败**：crash-recovery 返回错误 → Toast 显示真实错误文案；恢复类错误另给 CLI 兜底 `shanhai task run <taskId> --resume --resumed-by manual-resume`。
9. **多标签页同时操作**：不做跨标签协同；以服务端状态为准，冲突按第 4 条处理。
10. **轮询性能**：观测页三段轮询互相独立；某一段失败不影响其他段；页面隐藏（`visibilitychange`）时暂停全部轮询。
11. **超长文本**：长文本超过 60 字符截断+省略号+title 悬停全文；id 一律等宽显示前 8 位+悬停复制全文（任务无标题字段，V0.1「标题」表述更正）。
12. **深链接与浏览历史**：hash 路由下 URL 天然可深链接——刷新/直开 `#/tasks/:id` 等完整 hash URL 可达（server 对 `/` 恒返 index.html，hash 由前端路由消费，无服务端 fallback 需求）；路由变更经 hashchange 自然入浏览历史；未知 hash 显示 not-found 视图（app.js:78 既有行为）+ 返回首页按钮。
