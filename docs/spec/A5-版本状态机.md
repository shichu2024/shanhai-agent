## 1. 版本状态机（v1 冻结 + v1.1 Reviewed 环扩展，D-10）

```text
Draft ──release──▶ Released ──deprecate──▶ Deprecated
  │                                    ▲
  └──review──▶ Reviewed ──release（含 --no-pointer）──▶ Released
```

| 状态 | 语义 | 任务可绑定 | 指针可指向 |
|---|---|---|---|
| `Draft` | 已注册快照，未发布 | 否（仅显式 `--draft` 测试运行，不进正式队列） | 否 |
| `Reviewed`（v1.1） | 已过 review 检视门：**流程签核 + 变更面受控检视**（非完整质量判定——诚实表述） | 否（仅显式 `--reviewed` 测试运行） | 否 |
| `Released` | 正式可用 | 是 | 是（current 与 canary 指针，§4a） |
| `Deprecated` | 已废弃，保留审计与查询 | 否（存量任务继续跑完，新任务拒绝） | 否 |

**规则：**

1. 迁移封闭集：`draft→released`、`draft→reviewed`、`reviewed→released`、`released→deprecated`。**无回退边**（Deprecated 不可复活；**Reviewed 不可退回 Draft**——质量门判定不可撤销，只能重新注册新版本）。**直发保留**（`draft→released` 不经 Reviewed 仍合法，D-10——第一阶段存量行为不变）；
2. 状态迁移只改 `AgentVersion.status` 列（A1 §5 唯一例外），每次迁移追加审计事件（A6 §5）；
3. **当前版本指针：** `Agent(currentVersionId)` 单列指针；`release` 默认同步移指针，`release --no-pointer`（v1.1）发布不移指针（专供 canary 入口，D-12），`rollback` / `promote`（v1.1）显式移指针；
4. 回滚 = 移动指针，**不产生新版本、不修改任何快照**（不可变性保持）；
5. 回滚目标约束：仅可指向同 agentId 下状态为 `Released` 的版本（Draft/Reviewed/Deprecated 不可为目标）；
6. **deprecate 指针目标约束（P2-6 修订；v1.1 扩展）：** 禁止 deprecate **当前指针目标版或 canary 指针目标版**——CLI 返回结构化错误并提示，写 `RejectedRequest(kind='cli_operation')` 审计。**指针变更的显式语义集（v1.1，D-12）：** `release`（移 current）/ `release --no-pointer`（发布不移）/ `rollback` / `promote`（canary→current + canary 清零）/ `canary set/clear`（只动 canary 指针）——原则「**指针变更 = 显式操作 + 审计事件**」不变，枚举扩展；无任何隐式漂移（自动清指针/自动前移均否决）。

**review 检视门（v1.1，D-10）——diff 驱动最小检视清单：** `review` 命令自动生成与同 agentId **上一 Released 版本**的 Spec diff，人工逐项确认 5 项：① 工具集变化（风险等级上调标红）；② 预算变化（maxModelCalls/maxTokens 增幅 >50% 标黄）；③ mission 职责/非职责边界变化；④ approvalPolicy 变化（新高风险工具准入）；⑤ input/outputContract 结构变化。reviewGate 三档（A1 §2 evaluationPolicy.reviewGate）：`manual`（默认，交互逐项确认）/ `assertions`（自动跑契约断言 + diff 报告 + 人工确认）/ `none`。任一失败 → 拒绝迁移 + RejectedRequest 审计。`version_reviewed` 事件载荷：`{evalId?, checklist: [{item, verdict, note?}], diffAgainst: <上一 Released versionId>}`，`evaluationId` 列回填。

## 2. CLI 命令表（v1 + v1.1 增补命令族）

| 命令 | 语义 | 副作用 |
|---|---|---|
| `shanhai agent register <spec.json>` | 注册快照（A1 §7） | 新 AgentVersion(draft) + `version_registered` |
| `shanhai agent release <agentId> <versionId> [--no-pointer]` | 发布（**--no-pointer 为 v1.1**：发布不移指针，canary 入口） | status→released +（默认）指针移动 + `version_released`（载荷含 noPointer:bool） |
| `shanhai agent review <agentId> <versionId>` | **v1.1**：Draft→Reviewed 检视门（§1 检视清单） | status→reviewed + `version_reviewed`（含清单载荷）+ evaluationId 回填 |
| `shanhai agent deprecate <agentId> <versionId>` | 废弃（current/canary 指针目标版 → 拒绝，见 §1-6） | status→deprecated + `version_deprecated` |
| `shanhai agent rollback <agentId> <versionId>` | **指针回滚** | 仅指针移动 + `version_rollback`（审计） |
| `shanhai agent canary set <agentId> <versionId> --weight N` | **v1.1**：设置灰度（目标须 Released 且 ≠ current，§4a） | `canary_configured` 审计 |
| `shanhai agent canary clear <agentId>` | **v1.1**：灰度归零（立即） | `canary_configured` 审计 |
| `shanhai agent promote <agentId>` | **v1.1**：canary→current 晋升（report 判据输出为建议，**决定权留人**；数据不足输出 insufficient-sample） | current 指针移动 + canary 清零 + `version_promoted` 审计 |
| `shanhai agent report <agentId> [--since]` | **v1.1**：按 assignmentSource 分组通过率对比（C2 聚合口径复用）+ 旁挂三只读单列（**受工具升级影响的 Spec**[终审 R-5] / 审批超时计数 / staleQueued+stalePaused） | 无 |
| `shanhai approval list [--pending] / show / approve / deny` | **v1.1**：审批命令族（approve 只写 decision，迁移权归 resume，A3 §5） | 见 A3 §5 规则 |
| `shanhai task run --resume <taskId>` | **v1.1**：续跑挂起任务（持有 Paused→Running 迁移权，A3 §5） | 见 A3 §5 规则 |
| `shanhai agent list <agentId>` | 版本链列表（版本号/哈希/状态/时间） | 无 |
| `shanhai agent show <agentId> [<versionId>]` | 快照内容/元数据查看（默认当前指针） | 无 |

`rollback` / `canary set` / `promote` 失败模式：目标不存在 / 非 Released / 即当前指针 /（canary）等于 current → 结构化错误 + RejectedRequest 审计（CLI 侧拒绝同样留痕，与 T2 同源）。

## 2. CLI 命令表

| 命令 | 语义 | 副作用 |
|---|---|---|
| `shanhai agent register <spec.json>` | 注册快照（A1 §7） | 新 AgentVersion(draft) + `version_registered` |
| `shanhai agent release <agentId> <versionId>` | 发布 | status→released + 指针移动 + `version_released` |
| `shanhai agent deprecate <agentId> <versionId>` | 废弃（当前指针目标版 → 拒绝，见 §1-6） | status→deprecated + `version_deprecated` |
| `shanhai agent rollback <agentId> <versionId>` | **指针回滚**（03 号 R-1：A5 唯一可演示部分） | 仅指针移动 + `version_rollback`（审计） |
| `shanhai agent list <agentId>` | 版本链列表（版本号/哈希/状态/时间） | 无 |
| `shanhai agent show <agentId> [<versionId>]` | 快照内容/元数据查看（默认当前指针） | 无 |

`rollback` 失败模式：目标不存在 / 非 Released / 即当前指针 / **即 canary 指针目标（v1.2 注记，批次三 §4.5-1/A-7：防 current==canary 非法态，与 deprecate P2-6 防护对称——先 canary clear 或换目标）** → 结构化错误 + RejectedRequest 审计（CLI 侧拒绝同样留痕，与 T2 同源）。

**report 分母口径（v1.2 注记，D-23 冻结，批次三成文）：** `contractPassRate` 分母 = **tasks − cancelled**（治理性取消是治理决策非质量信号，排除以防稀释通过率）；每组输出 `excludedCancelled` 计数（口径可见、可复算）；分母为零（小组全为治理性取消）→ `contractPassRate = null` 且 promote 判据输出 `insufficient-sample`（不假装给答案）。**跨轮灰度混叠警示列（§4.5-3）：** 判据窗口（`--since` 起，缺省全史）内存在轮次边界事件（`canary_configured` / `version_promoted` / `version_rollback` 审计序列切轮）→ 输出 `window-straddles-rounds` 警示 + 边界时间戳；不自动切窗，窗口裁剪权恒在操作者（决定留人）。

## 3. 版本组成（重建基线 §20.1）

一个 Agent 版本 = 下列要素的**整体快照**，全部源自同一份 Spec 注册（不允许要素级独立漂移）：

| 要素 | 载体 | 版本化方式 |
|---|---|---|
| Spec 全文（identity/mission/contracts/policies） | `AgentVersion.specSnapshot` | 整体快照，contentHash 标识 |
| Prompt | Spec 内嵌于 mission/工作流描述 → 以 specSnapshot 承载 | 同上（无独立 Prompt 版本表——T1 的「Prompt 版本」= 快照哈希定位【设计决策点，欢迎挑战】） |
| 工具集 | Spec 声明的 toolId + 风险等级清单（快照内） | 工具本体版本由 Tool Registry 承载，任务绑定时记录运行时解析到的工具实现版本（A6 版本绑定事件） |
| 模型 | `modelPolicy`（快照内） | 同上 |

## 3a. 灰度发布：双指针 + 权重分派（v1.1 新增，D-12）

**Agent 表增列：**

| 字段 | 类型 | 默认 | 约束 |
|---|---|---|---|
| `canaryVersionId` | TEXT NULL | NULL | 只能指向同 agentId 的 **Released** 版本；不得等于 currentVersionId；设置入口 = `release --no-pointer` + `canary set`（结构可达，终审 P1-2 修复） |
| `canaryWeight` | INTEGER | 0 | 0–100；0 = 无灰度（缺省 = 第一阶段行为） |

**分派规则（版本绑定原则不变）：** 任务创建入口（A3 §3.1 落库前检查②指针解析处）按 `canaryWeight` 概率分派 stable/canary 指针 → 解析出的 agentVersionId **创建时一次性固化**进 TaskRecord（此后指针移动不影响已创建任务）；`assignmentSource`（stable/canary/explicit）落 TaskRecord 与 `task_created` 事件载荷（含当时双指针值）——灰度期间任一任务可回溯「为什么进了金丝雀」。

**晋升判据（机械输出，人裁决）：** promote 建议判据 = 金丝雀组契约通过率 ≥ stable 组 − 5pp 且样本 ≥ 20（阈值可配）；**样本不足（<20）输出 `insufficient-sample` 状态**（单机量级常不可达——系统不假装给了答案）。回退 = `canary clear`（立即，审计）。

## 4. T3 发布安全断言（用户硬性规则，冻结）

线上/发布产物**不得包含任何模型与密钥，仅支持配置**：

1. Provider 配置一律 `config.example` 模板 + 环境变量/本地配置注入；仓库与发布物只留占位；
2. `ModelGateway` **无配置即拒绝启动**（启动自检：白名单与密钥缺失 → fail-fast，不降级运行）；
3. 发布产物扫描：已知密钥格式正则（sk-/AKIA/ghp_/xox 等常见前缀与模式）+ 模型权重文件检查（扩展名/魔数：.gguf/.safetensors/.pth/.onnx 等）——**零命中方为通过**，命中即拒绝发布；
4. 扫描机制与开源前置待办（定稿 §11-2 仓库公开前清理）复用同一实现。

### §4a. 批次四成文注记（口径显式化，零行为变更，§4.7-6）

1. **健康面板 P95 采样口径（LIMIT 10）：** `agent report` 的 T1 单查询 P95 实测采样取**最近 10 个任务**（`task_record ORDER BY createdAt DESC LIMIT 10`，`report.ts`）——非全量口径；任务数 >10 时 P95 为近期样本估计，样本不足或未注入 t1 查询时输出 null（不假装给答案）。
