## 四、批次三变更明细

**§4.3 能力趋势（D-39，纯只读现算、零存储、零新迁移）：**
- `src/modules/trend.ts`（新增）：`buildCapabilityTrend(db, trace, agentId, {since, until, bucket})`——时间桶（day/week，week=ISO 周起始日）× agentId 聚合四面：
  - 任务面：任务量/契约通过率——分母/分子与 report **逐字相同 SQL 谓词**（`countedInContractRate = 1 AND t.status != 'cancelled'`，落盘谓词消费，非同常量现算）；分母 0 → null（无分母不假装）
  - 失败面：subClass 分布（同排除口径，时间列同任务面 t.createdAt）
  - 记忆面：memory_state_changed 按桶计数——trace_index 按 eventType 定位（经 task_record 连接收敛到该 agent 的 taskId 集）→ 定向文件读取（只读命中文件），**不整库扫描 JSONL**
  - 断言面：capability_registry 各状态条目数按 **createdAt 列**分桶（登记即事实，P3-4）
  - 诚实边界：coverage 仅记忆面单独标注 `coverage-from-memory`（首个该类事件时间戳，全史不受窗口裁剪）；任务/失败面全史不标注（P3-5）
  - 边界归一：since/until 裸秒形态下界补 `.000000000Z`、上界补 `.999999999Z`（字符串比较亚秒漏判防御，批次二 stale 锚点先例同款）；非法输入 → `TrendError`（invalid_bound/invalid_bucket）结构化拒绝
- CLI：`shanhai capability trend <agentId> [--since] [--until] [--bucket day|week]`

**§4.4 自我认知报告（D-40/D-41，组合只读制品、永不存储）：**
- `src/modules/insight.ts`（新增）：`buildAgentInsight(deps, agentId, {versionId, since})` 四层拼合：
  - 声明面：`INSIGHT_CARD_FIELD_KEYS = [agentId, versionId, specVersion, contentHash, mission, nonGoals, tools]` **常量导出 + 实现消费同一导出 + 测试逐字段存在性断言**（D-41 纪律同款，CARD_FIELD_KEYS 先例）；直接取 buildAgentCard 输出
  - 断言面：active 条目（counts + entries）+ open candidates 摘要计数（total/evidencePending）；无 Registry 条目 → 空清单 + 提示（不是错误）
  - 行为面：趋势缺省近 30 天窗（day 桶）；无任务数据 → `insufficient-sample`（不假装）
  - 限制与证据摘要：非 retired limitation 条目 + 各面证据引用计数（by kind，不展开 payload）
  - derived 接线：insight 构建时 `recomputeDerived()`（§4.2 生成时机：capability list / agent insight 同款）；「永不存储」指 insight 制品本体零写入，derived candidate INSERT 是 §4.2 既有语义（登记即事实），两者不冲突——dbDump 断言在 settle derived 后对 insight 双调用验证
- CLI：`shanhai agent insight <agentId> [versionId] [--since] [--json]`（缺省人类可读四层摘要；--json 导出完整结构供人工归档——归档是人动作，非系统行为）

## 六、随批视野评估结论（任务描述要求项）

### P3-①（批次二验收沉淀）：R2 全量扫描增量缓存——**结论：不做**

理由：
1. **规模前提未达**：OTel 触发线（Trace 事件 >10,000 或 T1 P95 >500ms）未触发；本批探针 60 事件库 insight（含 R2 重算）33.0ms，量级余量充足；
2. **零存储纪律**：D-39/D-40 确立本层只读现算原则——R2 结果缓存会引入第二真相源与写路径，与「趋势不落快照」取舍同源（设计 §13-1）；
3. **成本已被幂等收敛**：derived INSERT 被跨全状态同义查询短路，扫描成本是惰性触发（仅 list/insight 时）的一次性线性读取；
4. **降级路径已备且更优**：超线时「降采样/窗口收窄」先于缓存（§12 假设 #1）；缓存层登记为规模扩大时项（§14.6 insight 增量缓存）。
→ 重估触发条件：OTel 健康面板 `triggered=true` 实际出现。

### §6-4 双清单互见（capability list ↔ evolution list 同 evidenceRefs 交叉提示）——**结论：登记延后**

理由：
1. **形状不对齐**：evolution_candidate.evidenceRefs=`[{taskId, agentVersionId, subClass, occurredAt}]` 与 capability_registry.evidenceRefs=`[{kind, id, occurredAt}]` 结构不同，互见需 failure ref ↔ subClass/taskId 映射层——是新读侧聚合，非「只读交叉提示」一行可比；
2. **收官批范围纪律**：批次三范围=§4.3+§4.4+汇编，新增 CLI 输出面属扩界（任务描述硬约束「不得扩界」）；
3. **治理收益待真实数据**：双生候选并存场景尚未真实发生（R1 与 evolution repeated_failure 判据同源但聚合键/窗口不同），提前实现提示可能长期空转；
4. **延后落点明确**：与女娲演进工坊（第六阶段）合并评估——evolution 面改造时一并接互见（同源证据双引用允许的 §5 分权表既有口径不变）。
