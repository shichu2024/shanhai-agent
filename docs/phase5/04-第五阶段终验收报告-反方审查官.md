## 六、成立部分（为什么成立）

1. **同谓词机制是真防线而非措辞**：trend/report/R1 三处消费同一落盘谓词（写侧 EXCLUDED_FROM_CONTRACT_RATE 单一源物化后的落盘事实），且存在「常量变更后逐桶相等」的可失败回归断言——旧同常量现算机制下该断言必假。这是 V0.2 P1-1 修订的完整兑现。
2. **「永不存储/只读派生」纪律全程一致**：Evidence Store（零表）、trend（零快照）、insight（制品零写入）、Agent Card（先例）四个只读面同一模式，dbDump 断言形态统一，无一处以「 convenience」引入第二真相源。
3. **状态机与审计留痕完整**：三态唯一迁移边 + retired 无出边 + decidedAt/decidedBy + decision 区分（confirm/retire/dismiss 记审计载荷）——表内简洁、语义完整。
4. **诚实边界不假装**：分母 0 → null、无数据 → insufficient-sample、空 Registry → 空清单非错误、对账分叉 → consistent=false——四个「不假装」出口全部有断言。
5. **覆盖率单调递升**（92.84→93.15→93.28→93.55→93.85→93.87）证明逐批 DoD 门在第五阶段继续有效。

## 七、特别要求回答

1. **最可能失败环节**：规模扩大后 R2 全量扫描（trace JSONL 全读）延迟越线。防线已备：OTel 触发线监控 + 降级路径（降采样/窗口收窄）优先于缓存，重估条件明确（triggered=true），非裸奔。
2. **最大影响假设**：「derived 判据阈值（≥3 次/≥50%/30 天窗）在真实数据上有信号价值」。若阈值失准，系统退化为空转 Registry——不产生错误断言（人工确认制兜底），但价值缩水。已登记「真实数据后重估」，属第六阶段活。
3. **责任模糊环节**：无。四件套边界、三分权、审计留痕均已落到具体模块。
4. **理论可行现实难落地**：无新增。§6-4 双清单互见是唯一接近项，已按「形状不对齐需映射层」如实登记延后而非硬做。
5. **不必要复杂度**：无越界实现——三批交付与设计 §4.1~§4.4 逐节对应，未见设计外私增面。
6. **只保留一半时的取舍**：保 Evidence Store + Registry 状态机（可信度载体），缓趋势 + insight（读侧切片可后补）——数据地基先于展示面。当前全量交付不冲突。
7. **如何证明修订后更好**：P1-1 的可失败断言（常量变更逐桶相等）即是证明机制本身；本阶段无需进一步证明。
