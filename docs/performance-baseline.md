## 双跑波动实测

同一工作负载连续两次运行（300 次/端点交错采样）。**差异口径：|run1 − run2| / 较大值**（逐端点取最差）：

- **P50 双跑差异：最差 12.8%**（`/api/evolution`，1.17/1.02ms），全部端点 < 15% **通过线达标**。
- **P95 双跑差异：最差 14.7%**（`/api/agents/:id/insight`，4.29/3.66ms），全部端点 < 15%。
- CLI 冷启动 P50 差异 0.3%（372.62/373.81ms）。

**采样方法学的实证记录**（为什么缺省是 300 次交错轮询）：

| 方案 | 双跑 P50 最差 | 双跑 P95 最差 |
|---|---|---|
| 300 次/端点，交错轮询（终版双跑） | **12.8%** | **14.7%** |

- 数值出处：归档 `perf-run1.json` / `perf-run2.json`（`D:\code\shanhai-wp-archives\wp235-delivery\`）逐端点按上述口径复算，可独立复核。
- 建档期开发过程中曾以更小样本（60/150 次）与连续块采样试跑并据此选定缺省口径，但**试跑原始数据未随批归档**（临时 dataDir 随脚本清理删除，已不可恢复、无法区分与复核各方法学行的原始实测），具体数值不在此列——定量以终版双跑为唯一锚点（TASK-241 修正备案）。

亚毫秒级延迟对共享开发机的调度抖动高度敏感（后台负载/CPU 降频直接影响尾部分位）；交错轮询让各端点采样在时间轴均匀铺开、环境漂移同窗共担，是缺省口径。终版双跑两项分位均达 <15% 线；即便如此 P95 最差仍达 14.7%，**P95 尾部应视为噪声主导的参考值**——未来复跑若 P95 单项超线而 P50 稳定，应先排查环境再下回归结论。

## 复跑方法

```bash
npm ci && npm run build          # 须先有 dist/cli.js
node scripts/perf-baseline.mjs --out perf.json
# 可选：--port 17970 --samples 300 --cli-samples 16
```

- 脚本自起独立临时 dataDir + 种子（复用 smoke/walkthrough 种子机制：CLI 基础种子 → SQLite 直写扩展种子；13 任务多状态 + trace + 审批 + 能力 + 演进），起 dist 门户打点，跑完 taskkill 整树终止进程并删除临时 dataDir（exit 确认零残留）。
- 建议复跑两次对照波动；结论以 P50 为主锚。
- JSON 归档形态含 meta（repo SHA/node/机器）与逐端点 n/min/max/P50/P95/bytes，可直接 diff。
