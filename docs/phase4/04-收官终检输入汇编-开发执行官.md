## 四、批次四变更明细

**Agent Card 只读派生（§4.5，D-33，A-22）：**
- `src/modules/agentCard.ts`（新增）：`buildAgentCard(row)` 纯函数，从 AgentVersion 快照行现算；字段集严格按 §4.5 表（身份锚定 4 字段 / mission·nonGoals 截断摘要 / tools[] 含 controlledFields 键名摘要 / 契约 digest+类型摘要 / budgets·approvalPolicy·evolutionPolicy 治理姿态）；防御性截断 `CARD_MISSION_MAX_CHARS=200`
- `registry.agentCard(agentId, [versionId])`：缺省当前指针；draft 快照同样可导出（派生面不设状态门）；结构化拒绝（无指针 / 跨 agent 版本）；**零存储写入、零审计事件**（派生制品永不存储——每次现算，零一致性维护）
- CLI：`shanhai agent card <agentId> [versionId]`（usage 增补）；不做 A2A 端点、不做网络发布
- contentHash 字段保留（取自快照行）——按 V0.2 修剪，未建一致性断言（只读现算无漂移面）

**P3-2 fail-fast（随批携带，行为变更属预期演进）：**
- `config.ts` `parseMcpSection`：`mcp.resultMaxChars` 非法值（≤0 / 非数字 / 非有限数）→ `ConfigError` fail-fast 拒绝启动（原批次二静默回退缺省）；合法值向下取整与缺省行为不变；config.example.json 注释同步

**择项增强（V0.2 降格项，本批已做）：真实公开 stdio MCP server 端到端**
- server：`@modelcontextprotocol/server-everything`（2026.8.31，npm 公开包，本地安装后以 `node` 直启——Windows 下 `spawn npx` 不可解析 .cmd，属平台事实非设计缺口）
- 流程：`shanhai tool mcp connect everything --yes` → spawn → initialize → tools/list 发现 13 工具 → 批量登记（全 external / source=mcp:everything / 缺省 L3）→ `McpToolBridge.call('everything-echo')` 真实调用 → 返回带边界标记 `<tool-result source="mcp:everything">Echo: …</tool-result>`
- 结论：接入/发现/登记/调用桥/边界标记全链对真实 server 成立（夹具语义面结论外推获实证）
