## 1. 定位与价值主张（依用户确认调整）

**第一价值主张：完整验证流程的可运行参考实现。**

用户目标为「从零了解一个 Agent 完整的验证流程」——第一阶段交付一条可亲身运行、可逐步拆解、端到端跑通的验证链：**定义（Spec）→ 执行（Runtime）→ 证据（Trace）→ 评估（Evaluation）→ 验收（Acceptance）**。T1/T2 断言保证这条流程可被亲手检验：任一次失败都能查到当时生效的版本，任一次拦截都能举证。

- **目标形态：开源项目**（用户确认）。差异化论证（08 号，经三轮滚动抽查收窄后的版本）降级为开源定位的**支撑材料**：山海司不可替代的空间收敛为 **D4（受控演进）整条主张 + D2（证据认知）中的能力结论制品层**；此论断为 2026-09 可校准快照（S6），按 08 号 §3.9 滚动机制维护。
- **诚实校准**（15 号 §2-问①）：A-1 原口径（长期运行生产资产场景）未被确认也未被否定；A-5 痛点清单定性为「用户认知框架」而非「生产实证」。本定稿全文按此口径叙述，不作夸大。

## 3. 三条设计底线（不可削减）

1. **Spec 必须被 Runtime 强制执行**——否则「规格驱动」不成立；
2. **Trace 从第一个任务起落盘**——评估、能力快照与第二阶段白泽/女娲的全部输入；
3. **AgentVersion 不可变**——注册时 Spec 全文快照入库，Git 仅承载审计历史与 diff。

## 5. 核心机制（冻结）

### 5.1 Task 状态机（attempt 模型）

状态集 `Created / Queued / Running / Paused(空壳预留) / Succeeded / Failed / Cancelled`；Succeeded/Failed/Cancelled 为真终态无出边；重试 = Running 内新 attempt（`maxAttempts` 默认 3，Spec 可覆盖）；Timeout 非独立状态，任务级/调用级超时分别映射为 Failed 的 failureClass；含崩溃恢复迁移（重启发现非终态遗留 → Failed:Runtime(CrashRecovery)）。完整迁移表（触发事件 / 持久化点 / A4 映射三列）见 03 号 §3.2。

**审计边界一行规则**：TaskRecord 落库前的校验失败 → RejectedRequest 审计（不创建 Task）；落库后的任何校验失败（含防御性重复校验）→ Created→Failed。

### 5.2 预算与工具策略

- 预算：`maxModelCalls` + `maxTokens`（任务级）；usage 以 provider 返回为准、缺失本地估算并标注 `estimated`；
- 工具风险闸门：L0–L2 放行（L1/L2 审计；L2 必须声明受控字段：参数范围/目标白名单），L3/L4 拦截；
- 拦截反馈：结构化 `policy_denied`（含 reasonCode）；`maxConsecutiveDenials` 默认 2，超限 → Failed:Policy(PolicyBlocked)，归因不漂移。

### 5.3 版本与发布安全

- 版本状态机：`Draft → Released → Deprecated`（Reviewed 随第二阶段审批流引入）+ 指针回滚 CLI；
- **T3 发布安全断言（用户硬性规则）**：线上/发布产物**不得包含任何模型与密钥，仅支持配置**——Provider 配置一律模板 + 环境变量/本地配置注入，仓库与发布物只留 `config.example` 占位；ModelGateway **无配置即拒绝启动**；发布产物密钥扫描（已知密钥格式正则 + 模型权重文件检查）零命中方为通过。

## 6. 验收标准（冻结）

| 项 | 标准 |
|---|---|
| C1 端到端演示 | 完整任务生命周期（注册→校验→执行→Trace 落盘→终态与归因正确）；**含 ≥1 个真实业务只读任务**（默认候选：对本仓库 `docs/` 做只读分析并产出结构化摘要） |
| C2 契约通过率 | 同一任务 N≥10 次（实验设计 N=30，3 类 Spec × 10）；**首次通过率主指标、≥80% 为决策线**（<80% 触发显式第二阶段决策点，非隐式兜底）；报告附 A4 失败分类分布 + Wilson 置信区间；`infra_failure` 与 `provider_rejected_schema` 排除出契约失败率 |
| C3 反向验收 | ① 越权 Spec 注册即拒；② maxModelCalls=1 + 第二次调用 → 确定性截停 Failed:Runtime(BudgetExceeded)；③ 连续请求被拒工具 ≥2 次 → Failed:Policy(PolicyBlocked) |
| T1 证据可用 | 给定任一 Failed 任务的 Trace，单一查询返回当时生效的 Spec 版本及其 Prompt/工具版本关联 |
| T2 拦截可举证 | 给定任一 Agent 版本，单一查询返回其运行期内全部越权尝试与拦截点（RejectedRequest + policy_denied 记录） |
| T3 发布安全 | §5.3；命中即拒绝发布 |
| WP-A | 每项满足 DoD（§4.1） |

T1/T2 答不出 = 空心地基 = 整体不通过，不得以「功能演示正常」替代。
