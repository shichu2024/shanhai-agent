## 3. 立项论证与差异化定位 V0.2（全文修订版）

### 3.1 总体论点（收窄版）

> **现有 Agent 技术栈回答「如何快速构建一个 Agent」，山海司回答「如何工程化地运行、认知、约束和演进一个 Agent」。经独立联网核查确认：截至目前，没有任何现有方案提供「版本化 Spec 制品 + 证据认知 + 评估准入 + 受控演进」的完整闭环——山海司的定位空间真实存在；但生态正在快速逼近。经第 5 轮滚动抽查收窄后，山海司真正不可替代的差异化收敛为：D4（受控演进）整条主张，与 D2（证据认知）中的能力结论制品层（审计证据层已有商业治理平台强替代）。**

### 3.3 差异化主张（按可替代性排序：D2 > D4 > D1 > D3 > D5）

**弱替代矩阵：**

| 主张 | 组合方案中的最弱可行替代 | 可替代性 |
|---|---|---|
| **D2 证据认知** | 审计证据层有强替代（已商业化的治理平台可产出合规证据）；能力结论制品层无可替代 | **部分无可替代**（第 5 轮抽查收窄，见 D2 正文） |
| **D4 受控演进** | 无 | **无可替代** |
| D1 规格强制 | Agents SDK approvals / LangGraph interrupt（命令式）+ 代码审查纪律 | 弱替代存在 |
| D3 评估准入 | promptfoo/Braintrust CI gate | 弱替代存在 |
| D5 版本工程 | Langfuse prompt 版本标签 + 团队约定 | 弱替代存在 |

**D2 证据认知（白泽原则）——第一支柱（第 5 轮裁定收窄口径）**：分两层表述——**审计证据层有强替代**（已商业化的 Agent 治理平台可产出合规/审计证据，叙事校准：「治理平台做合规证据，山海司做能力认知与演进闭环」）；**能力结论制品层无可替代**——能力画像 = 任务样本 × 通过率 × 版本切片的可保鲜一等实体，现有方案（含商业治理平台）均不提供该制品。Agent 的能力画像不由模型自述决定，而由运行证据 + 评估结果 + 人工确认形成可追溯证据链。第一阶段的「Trace 从第一个任务起落盘」底线即其地基——**这是第一阶段设计与差异化论证天然一致的支点**。可证伪条件：若竞品提供可作为下游决策输入、随版本更新自动保鲜的能力画像制品【待验证】。

**D4 受控自我演进（女娲原则）——第二支柱**：失败记录与评估结果自动生成改进候选，经隔离实验、回归验证、（高风险时）人工审批后发布，每步可审计可回滚。竞品的「学习/记忆」均为隐式积累，不可验证、不可回滚、不可归因。可证伪条件：竞品出现「候选→实验→准入→发布」的流程制品【待验证】。

**D1 规格驱动 + 运行时强制（收窄口径）**：差异不在「有无强制点」（interrupt/approvals 已存在），而在**制品化与治理面**——Spec 是声明式、版本化、可校验、可跨 Agent 治理的独立制品，强制与拦截审计围绕制品展开，而非散落在各处命令式代码中。可证伪条件：主流框架原生提供声明式版本化 Spec 制品 + 围绕它的拦截审计【待验证】。

**D3 评估约束发布（弱化）**：eval-gated CI 已是生态标配做法，山海司的差异仅剩**平台级「版本不可变 + 准入 + 回滚」硬闭环**（评估不过则在平台层拒绝发布，而非依赖各团队 CI 自律）。此项是平台便利而非不可替代差异，不再作为独立主推主张。（注记【14 号 ND-3】：Anthropic 平台已提供 prompt 级版本管理 + 标注测试集评估 + 回滚——上游正逐要素补齐，D3 剩余差异空间进一步收窄；但范围仍限 prompt 单要素，非 Agent 全要素版本-准入-回滚闭环，主张维持成立。）

**D5 全要素版本工程（弱化）**：Prompt/工具/知识/记忆/模型/Spec 的版本关联图谱。竞品有 prompt 版本标签级弱替代；山海司差异在跨要素关联的完整性。与 D3 同降为支撑性主张。（注记【14 号 ND-3】：上游版本管理已推进至 prompt 单要素（含评估与回滚），跨要素关联仍无承载——差异收窄但未被消除。）

### 3.4 与开源组合方案对比（修正版：先 steelman）

| 维度 | 开源组合方案（LangGraph + Langfuse + promptfoo + 自研 Guard） | 山海司自研 |
|---|---|---|

| 生态 | **插件、模板、社区支持成熟**；组件可按需替换 | 需自建生态 |
| D2/D4 两条主张 | **无法覆盖**（观测平台不形成能力结论；无演进闭环）——这正是组合方案的结构性天花板 | 原生闭环 |
| 治理与审计 | 各组件粒度不一，跨组件审计需自行拼装 | 统一审计边界（玄武单点） |

### 3.6 为什么是现在（A-4 升格为双面证据）

2026 年规格/治理层已出现多个第三方入场：LangGraph 之上的 policy-as-code 层、声明式 Agent 规格框架（学术与工程侧）、「Agent Contract」理念主张（来源见 §3.2 第五类）。这构成**双面证据**：

- **窗口面（支撑紧迫性）**：行业已认可「Agent 需要规格与治理」这一问题，问题真实性不再依赖单一样本（A-5 的样本量短板被部分补强）；
- **威胁面**：入场者增多意味着「规格层」可能被上游或第三方做成事实标准；若 6–12 个月内发生，山海司差异化将收窄为 D2/D4 两条 + 集成便利，立项经济性需重估。上游还在**逐要素补齐闭环**——Anthropic 平台已提供 prompt 级版本 + 评估 + 回滚【14 号 ND-3，已核实】——窗口收窄再添实证（定稿风险节 A-4 条目须收录此信号）。

推论：**A-4 从「可等待的推测」变为「正在计时的窗口」**——这反而强化了第一阶段尽快落地 Trace/Spec 地基（D2/D4 的基础）的理由。

### 3.8 最脆弱的三个假设（更新：供决策官裁定时重点关注）

1. **A-1（场景真实性 + 目标形态）**——地基，合并提问一次解决（§8）；
