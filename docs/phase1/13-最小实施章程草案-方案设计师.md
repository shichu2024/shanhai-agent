## 4. 验收标准（冻结，引用为主）

1. **C1/C2/C3**：见 05 号 §4（C2 参数：N≥10、首次通过率主指标、≥80% 决策线、A4 失败分布随报）。
2. **T1**（12 号 S3）：给定任一 Failed 任务的 Trace，单一查询返回当时生效的 Spec 版本及其 Prompt/工具版本关联。
3. **T2**（12 号 S3）：给定任一 Agent 版本，单一查询返回其运行期内全部越权尝试与拦截点（RejectedRequest + policy_denied 记录）。
4. **C1 增补**（S4）：≥1 个真实业务只读任务——默认候选：对本仓库 `docs/` 做只读分析并产出结构化摘要。
5. **WP-A DoD**：三角色各一票 + 决策官终审（05 号）。
6. **验收不通过的处置**：修复后重跑对应项；T1/T2 答不出 = 空心地基 = 整体不通过，不得以「功能演示正常」替代。

## 5. 削减顺序（引用 01 号 §9.5，冻结）

1. 先砍 C1 示例 Agent 的丰富度（保留 1 工具，不做多轮对话）；
2. 再砍 StateManager 崩溃标记，接受重启后遗留脏状态（人工清理）；
3. 最后砍 A4/A5/A6 中与 Runtime 无直接执行依赖的文档细节（保留枚举定义，砍说明文字）。

**不可削减底线**：SpecValidator、Policy 强制检查、Trace 落盘、版本不可变。**另增**（12 号）：T1/T2 断言与假设 #4 实验属不可削减项。

## 6. 悬置与终止规则（S2，即刻生效，引用 12 号）

- 四问未复期间：WP-B/WP-C 不启动；纸面工作（规格草案、章程、定稿稿）可继续；
- 满 7 天未复：决策官提醒一次；满 14 天未复：issue 转 blocked，不新增讨论轮次；
- 用户答「①否」：决策官出终止性收敛裁定，10/11 号资产标注「可移植组合方案」，以「讨论完成、结论为不立项」收口——终止不是作废。

## 7. 演示降级预案（S5）

- S1/S2 类 Spec 演示正常路径：全链路（注册 → 任务 → Trace → 契约校验 → 版本关联查询）；
- S3 类 Spec 塌方时（假设 #4 实验预判）：叙事退至「分层契约规则已产出」（08 号 2.3 分支的文档化成果），不现场演示失败路径；
- 密钥不可用时：演示退至 Trace 回放模式（预录 JSONL），并显式声明「C2 验收顺延」。

## 8. 价值主张边界（S4，写入定稿的声明）

第一阶段交付的价值 =「**只读/低风险自动化 + 证据地基**」（Spec 强制 + Trace 落盘 + 版本不可变 + T1/T2 可查证）；带副作用的任务自动化属第二阶段（审批流 Paused/ApprovalRequest 就位后）。在第一阶段宣称超出此边界的价值均属过度承诺。
