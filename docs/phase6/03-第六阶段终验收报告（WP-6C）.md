### 2. P3-③ 非回环 bind Host 收紧评估（评估结论，成文不改行为）

**现状核实（代码级）**：`auth.ts` `hostAllowed()`——回环绑定（127.0.0.1/localhost）允许 {'127.0.0.1','localhost'} 双形态；非回环绑定仅允许**字面 bindHost**（端口任意）。Host 校验先于认证与路由（server.ts:209-213），不匹配 → 403 `host_forbidden`。

**评估**：

- **安全面：现实现已是收紧态，无可收增量。** DNS rebinding 攻击要求攻击者域名解析到绑定地址且浏览器携带该域名 Host 头——当前精确字面匹配下任何非字面 Host（含 DNS 名）即 403。唯一「更严」的选择是禁止非回环绑定，而 D-44 冻结口径为「非回环绑定允许（合法即放行）」，收紧=推翻冻结决策，非本评估职权。
- **附带发现（可用性，非安全）**：`--host 0.0.0.0` 通配绑定时 allowed=['0.0.0.0']，任何实际访问 Host（LAN IP/主机名）均 403——通配绑定事实上不可用（fail-closed，行为保守安全但无显式指引）。
- **结论：延后至后续阶段，列入遗留清单。** 理由：①安全上无收紧空间（上述）；②通配绑定全 403 是 UX 缺陷而非漏洞，处置属可用性改进（显式拒绝通配绑定并给出指引），价值独立于安全叙事，可随下次触碰 portal 的批次顺手携带；③多用户/远程暴露为本阶段非目标（D-44/§2.2），届时与监听策略统一设计。
